# Обновление до 2.1.1

[English](MIGRATION.md) · [История изменений](CHANGELOG.md) · [Эксплуатация](docs/operations.ru.md)

Версия 2.1.1 сохраняет конфигурацию, каталог инструментов и поддерживаемые ревизии MCP из 2.1.0. Рабочие ключи Avito остаются в вашей приватной конфигурации. Режим `--demo` использует вымышленные данные и включается только явно.

## Что нужно для вашей версии

| Установленная версия | Действия                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 2.1.0                | Установите 2.1.1 и перезапустите клиент или сервис; менять конфигурацию не требуется     |
| 2.0.x                | Прочитайте об [операциях с неизвестным результатом](#переход-с-20x) и исправлении сводки |
| 1.3.x                | Проверьте [HTTPS, регистрацию клиентов и отмену](#переход-с-13x)                         |

Для локальной установки через npm:

```bash
npm install avito-mcp@2.1.1
npx avito-mcp --version
```

Если клиент запускает сервер через `npx` с закреплённой версией, замените аргумент пакета на `avito-mcp@2.1.1` и переподключитесь. Для systemd используйте [инструкцию выпуска и развёртывания](docs/releases.md): установка npm-пакета в другом каталоге не обновляет работающий сервис.

## Переход с 2.0.x

Версия 2.1.0 изменила два сценария на обеих ревизиях MCP:

- Если запрос на изменение уже отправлен, но ответ потерян, сервер возвращает `OUTCOME_UNKNOWN` и `retryable: false`. Блокировка ключа идемпотентности не снимается по таймеру. Сначала проверьте результат в Avito; [порядок восстановления](docs/safety.md#lost-responses-after-a-mutation-v21).
- `avito_daily_overview` ограничивает историю расходов 270 днями и требует прочитать все страницы объявлений. На современной ревизии значение выше 270 отклоняется; legacy-промпт ограничивает его до 270.

Если создание платного продвижения вернуло ID заказа, а последующая проверка статуса не удалась, сервер сохраняет этот ID. Проверяйте существующий заказ вместо создания нового.

## Переход с 1.3.x

### HTTPS для удалённого OAuth

С версии 2.0.0 OAuth на публичном хосте требует HTTPS в `AVITO_MCP_HTTP_PUBLIC_URL`. Для локальной разработки разрешён HTTP на loopback. Настройте TLS-прокси и укажите его публичный адрес:

```bash
AVITO_MCP_HTTP_PUBLIC_URL=https://mcp.example.com
```

Смена адреса меняет OAuth issuer: сохранённые регистрации и токены сбрасываются, клиентам нужно авторизоваться снова. Примеры прокси находятся в [руководстве по HTTP](docs/operations.ru.md#удалённый-mcp-по-http-oauth-21). Параметры обхода HTTPS из `.env.example` предназначены только для разработки.

### Регистрация клиентов

Новые регистрации принимают HTTPS redirect URI либо HTTP на loopback, без фрагмента `#…`. Собственные URI-схемы приложений и обычный HTTP на публичном хосте отклоняются. Native-клиенты используют PKCE без `client_secret`; явно указанный web-клиент требует HTTPS callback вне loopback.

Сохранённые регистрации не перепроверяются при загрузке, но новые правила действуют при повторной регистрации. Без постоянного OAuth-хранилища клиентам приходится регистрироваться после перезапуска.

### Отмена запроса

С версии 2.0.0 `notifications/cancelled` прерывает работу на обеих ревизиях MCP. Современный клиент также может отменить запрос закрытием потока ответа. До отправки запроса ключ освобождается. После отправки операция изменения с ключом идемпотентности оставляет ограниченную по времени блокировку; повторный вызов получает `IDEMPOTENCY_HELD`.

Эта блокировка отмены отличается от бессрочной блокировки потерянного ответа, добавленной в 2.1.0. Коды причин и восстановление описаны в [руководстве по безопасности](docs/safety.md#lifting-a-held-idempotency-key).

### Зависимости и состав пакета

В 2.0.0 проект перешёл на раздельные пакеты TypeScript SDK v2. В 2.1.1 встроенный OAuth-сервер сохраняет переходную зависимость от прежнего authorization helper; внешний провайдер идентификации не требуется. Импорты из недокументированных путей `dist/*` не относятся к публичному API.

npm-пакет включает публичную документацию и примеры. Локальные исследования, рабочие заметки, ключи и runtime-состояние исключены. Имена инструментов и документированные допустимые схемы аргументов в этих версиях не менялись.

## Необязательный переход на новую ревизию MCP

| `AVITO_MCP_PROTOCOL_ERA` | Поддерживаемые ревизии      |
| ------------------------ | --------------------------- |
| `legacy` — по умолчанию  | `2025-11-25`                |
| `dual`                   | `2025-11-25` и `2026-07-28` |
| `modern`                 | Только `2026-07-28`         |

Начните с `dual`, если нужны современные клиенты вместе с существующими. stdio выбирает ревизию по первому сообщению до переподключения; HTTP проверяет каждый запрос отдельно. Подробности — в [разделе совместимости](docs/operations.ru.md#протокол-и-совместимость).

Современный HTTP использует лимиты `AVITO_MCP_HTTP_MAX_INFLIGHT=64` и `AVITO_MCP_HTTP_MAX_STREAMS=32` по умолчанию. Лимиты сессий продолжают действовать только для legacy HTTP.

## Проверка и восстановление

После обновления проверьте версию и `meta_health`, затем выполните [проверку только чтением](docs/adr/0002-canary-protocol.md), если доступ к аккаунту разрешён. Готовность HTTP-сервера сама по себе не подтверждает доступ к API Avito.

Чтобы отключить современную ревизию, установите `AVITO_MCP_PROTOCOL_ERA=legacy` и перезапустите процесс. Перед понижением версии пакета проверьте совместимость состояния и [инструкцию отката](docs/adr/0007-rollback-criteria.md). Сохраняйте блокировки идемпотентности и ожидающих действий: старая версия может не поддерживать новые защиты от повторения операций. Не удаляйте состояние ради запуска старой версии.

В issue укажите установленную версию, клиент и его версию, транспорт, режим авторизации, protocol era и ошибку без секретов. Ключи и ответы с данными покупателей должны оставаться приватными.
