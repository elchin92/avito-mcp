# Решение проблем

[Документация](README.md) · [English](troubleshooting.md) · [Подключение клиента](clients.ru.md)

Определите, на каком шаге возникла ошибка: запуск, чтение Avito, изменение данных или HTTP-авторизация. Начните с поля `type` в структурированной ошибке и журнала сервера. Перед публикацией удалите ключи и данные покупателей.

## Сервер не запускается

| Симптом                                  | Что делать                                                                                                                                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сервер отсутствует или ошибка `ENOENT`   | Выполните `node --version` и `npx --version` в терминале. Нужен Node 22.12+. У приложения может быть другой PATH: при необходимости задайте абсолютный путь к исполняемому файлу и перезапустите клиент. |
| Конфигурация сохраняется, но сервера нет | Проверьте [формат клиента](clients.ru.md): Claude/Cursor используют `mcpServers`, VS Code — `servers`, Zed — `context_servers`, Codex — TOML. Добавьте запись в нужный файл.                             |
| Первый запуск не успевает завершиться    | Выполните `npx -y avito-mcp@2 --version`, чтобы скачать пакет заранее. При необходимости увеличьте время ожидания в клиенте; пример Codex допускает 60 секунд.                                           |
| При запуске возникает ошибка настроек    | Сверьте имена и значения с [`.env.example`](../.env.example). В `Client_id`, `Client_secret` и `Profile_id` важен регистр; ID профиля должен быть числом.                                                |

Проверьте запуск пакета на изолированном демо:

```bash
npx -y avito-mcp@2 --demo
```

Демо использует вымышленные данные и не обращается к Avito. Его успешный запуск **не проверяет** ваши ключи и доступ к API Avito.

## Клиент подключён, но чтение не работает

| Симптом                 | Что делать                                                                                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Avito возвращает 401    | Проверьте, что ID клиента, секрет и профиль относятся к нужному аккаунту. Вызовите `meta_auth_status` с `probe: true` для проверки обновления токена. Инструмент возвращает метаданные, а не токен.                            |
| Avito возвращает 403    | Аккаунт может быть авторизован, но не иметь доступа к этому методу. Уточните требования метода в [поддержке API Avito](https://developers.avito.ru/).                                                                          |
| Нет нужного инструмента | Проверьте `AVITO_MCP_MODE`, списки разрешённых и запрещённых инструментов, затем перезапустите сервер. `meta_capabilities` показывает итоговые настройки. Выдача токенов и загрузка локальных изображений включаются отдельно. |
| Avito возвращает 429    | Посмотрите `retryAfter` и `meta_get_rate_limits`; подождите и сократите число одновременных запросов.                                                                                                                          |
| Список или отчёт пуст   | Проверьте аккаунт, фильтры, даты и страницы результатов. `items_get_items_info` не возвращает объявления сотрудников; перед выводом об ошибке прочитайте описание инструмента.                                                 |

Статус connected проверяет связь по MCP. Успешное чтение Avito дополнительно проверяет авторизацию и права на конкретный метод. `meta_health` и `avito-mcp --health` описывают локальное состояние сервера, но не доказывают доступность Avito.

## Изменение ждёт подтверждения или результат неизвестен

| Ответ                         | Что он означает и что делать                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Предпросмотр с `dryRun: true` | Рабочий запрос не отправлялся, ожидающее действие не создано. После одобрения отправьте отдельный вызов с `dryRun: false`.                                           |
| `requires_confirmation: true` | Действие ещё не выполнено. Проверьте его и вызовите `meta_confirm_action` по своей политике подтверждений либо `meta_cancel_action` для отмены.                      |
| `OUTCOME_UNKNOWN`             | Запрос на изменение отправлен, но ответ потерян. Изменение могло выполниться. До повтора проверьте реальный заказ, сообщение или объявление.                         |
| `IDEMPOTENCY_HELD`            | Ключ удерживается из-за неизвестного результата прошлого запроса. Сначала сверьте эту операцию с Avito. Новый ключ может привести к повторному выполнению.           |
| `TIMEOUT` или `NETWORK_ERROR` | Прочитайте ошибку целиком и поле `retryable`. Для изменения сначала выясните, дошёл ли запрос до Avito: ошибка сама по себе не доказывает, что данные не изменились. |

Следуйте [инструкции при потере ответа](safety.md#lost-responses-after-a-mutation-v21) и [процедуре снятия удержания ключа](safety.md#lifting-a-held-idempotency-key). Сохраняйте один ключ идемпотентности для одного намеренного действия; новый ключ не заменяет проверку результата.

## Не проходит HTTP-авторизация

Используйте HTTPS-адрес `/mcp` вашего сервера. Проверьте `AVITO_MCP_HTTP_PUBLIC_URL`, сохранение заголовка `Host` прокси-сервером и [настройку OAuth](operations.ru.md#удалённый-mcp-по-http-oauth-21). После смены публичного URL издателя токенов нужно заново зарегистрировать клиент. У работающего сервера `/readyz` сообщает о готовности, `/healthz` — о процессе.

ChatGPT web не читает локальный TOML Codex и не запускает `npx` на вашем компьютере. Используйте [инструкцию для веб-интеграции](clients.ru.md#chatgpt-web).

## Подготовьте полезное сообщение об ошибке

В [шаблоне бага](https://github.com/elchin92/avito-mcp/issues/new?template=bug_report.md) укажите:

- Установленную версию сервера, клиент и его версию, ОС и версию Node.
- Транспорт, `AVITO_MCP_PROTOCOL_ERA` и выбранный профиль или список разрешённых инструментов.
- Точное имя инструмента, аргументы с заменой частных значений, ожидаемый результат и структурированную ошибку.
- Короткие шаги воспроизведения, в том числе могло ли изменение уже выполниться.

`npm view avito-mcp version` показывает последнюю опубликованную версию: клиент может запускать другую. Версию подключённого сервера можно узнать из результата `meta_health`.

Журналы Claude Desktop: `~/Library/Logs/Claude/` в macOS или `%APPDATA%\Claude\logs` в Windows; журнал этого сервера — `mcp-server-avito.log`. В других клиентах используйте окно вывода или журнал MCP. См. [официальную диагностику локального сервера](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

Не прикладывайте заполненные `.env`, токены, настоящие сообщения покупателей, ID аккаунтов и экспорты личных разговоров. Об уязвимостях сообщайте через [приватный канал](../SECURITY.md#how-to-report), о нарушениях правил сообщества — через канал в [Code of Conduct](../CODE_OF_CONDUCT.md#enforcement).
